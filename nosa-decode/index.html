### GPU K/V accounting

In `candidate/coded`, each layer allocates two BF16 tensors of shape `[16, 64 × 64, 2, 128]`. The two tensors together occupy 67,108,864 bytes per layer and 2,147,483,648 bytes across 32 layers. The cold codec writes its prompt payload and descriptors to pinned CPU memory. Its fetch kernel reads those host buffers directly into the two hot tensors. The CUDA graphs reference those allocations. They have no additional K/V page staging buffer.

Each layer, request and KV head has 64 physical slots for complete blocks, including the writable tail. Each slot pairs K and V for one block identity. The update retains selected hits and assigns missing identities to vacated slots. The cache map and load mask contain integers. Thus the per-row upper bound is 64 distinct resident block identities, including the tail. The short- and long-prefix worker fingerprints independently report the same 2 GiB of hot allocation in `runs/coded/candidate/`.

The packed-bank experiments are ineligible. `candidate/resident` shares a decompression workspace inside the allocation but supplements the canonical 64 identities with a compressed bank. A row can hold 64 canonical identities plus up to nine additional identities. The frozen development check measured 1.247037× with both numerical cases passing. This timing is diagnostic only. `candidate/banked` could retain 76 compressed identities plus the tail and was dropped before a full-model run. Neither tree qualifies for selection.

The in-place predictor in `candidate/routed` writes speculative replacements directly into vacated hot slots. It keeps the original 64-slot allocation and restores the canonical slot order before attention. A short-prefix sweep checked unique physical IDs after each speculative update and matched the reference selected sets. Two proposed swaps per row reduced demand misses from 16,144 to 15,276 across the audited post-warmup layers, but throughput fell from 844.90 to 659.70 tokens/s. Four and six proposals fell to 509.49 and 454.50 tokens/s. The predictor and transfers cost more than the avoided misses. Evidence is in `runs/r2-route-sweep2.log`.

`candidate/graphfast` passed the frozen development check at 847.60 and 815.85 tokens/s, for a geometric-mean speedup of 1.340092×. It combines each layer's attention and feed-forward graph with preparation of the next layer, precomputes the CIS ordering for the current compression epoch and writes the residual addition directly to the graph input. Its cold codec, two GPU K/V tensors and canonical 64-slot replacement algorithm are the same as in `candidate/coded`. Both worker fingerprints report 2,147,483,648 hot K/V bytes. The two development recordings each contain 5,120 layer/request/head selections including warmup, with exactly 64 unique IDs in every selection. The full result is in `runs/r2-graphfast/check.json`.

The slot audit also checked the writable tail explicitly. For each prefix, all 5,120 selections in each of the graphfast and fused recordings contained the tail ID (256 or 510 respectively), and each contained 64 distinct IDs. The largest change between consecutive selections for one row was 15 blocks. Both implementations write every demanded block straight from pinned host memory to its assigned hot slot. The assignment drops the evicted identity before the slot is reused. The unchanged sparse selector uses pooled keys and scores to rank blocks. Those summaries cannot supply a K/V block to attention. The CPU K/V payload fingerprints were 12,884,901,888 and 21,407,727,616 bytes.
